# 安装版与商业化方案（2026-06-18）

## 1. 产品定位

shipin-cut 不替代剪映，而是负责剪映前面的混剪自动化链路：

素材导入 -> 字幕识别 -> 切片 -> 组合方案 -> 基础调整 -> 导出剪映草稿。

后续精修、字幕样式、贴纸、音乐、最终发布仍由用户在剪映中完成。当前已经稳定的剪映草稿导出、字幕体系导出和时长修复，是安装版商业化前的核心基础。

## 2. Storybound 参考形态

目标体验参考 Storybound：

- 用户下载一个 Windows Setup.exe。
- 双击安装后，桌面生成“视频混剪工具”快捷方式。
- 平时双击桌面图标启动软件。
- 首次或到期后输入兑换码才能继续使用。
- 兑换码可用于体验、续费、增加次数或增加使用时长。
- 额度用完或到期后，核心导出能力受限。
- 导出剪映草稿成功后，第一版提供“打开草稿文件夹”入口，并提示用户在剪映草稿箱中查找同名草稿。

## 3. Windows 安装版目标流程

最终用户不需要打开 VS Code，不需要手动运行 npm / Python，也不需要手动打开 localhost。目标流程是：

1. 下载 `视频混剪工具_Setup.exe`。
2. 双击安装。
3. 安装到 `%LOCALAPPDATA%\ShipinCut` 或 `Program Files\ShipinCut`。
4. 桌面和开始菜单生成快捷方式。
5. 点击快捷方式后启动本地后端和前端界面。
6. 检查兑换码状态并显示剩余额度或到期时间。
7. 用户导入素材、生成方案、导出剪映草稿。
8. 成功后点击“打开草稿文件夹”，打开对应草稿所在文件夹，并提示在剪映草稿箱中查找同名草稿继续编辑。

## 4. 技术路线对比

### 方案 1：Inno Setup + 本地启动器

- 生成 Windows Setup.exe。
- 安装前端 build、Python 服务、tools、ffmpeg、whisper、模型文件和启动器。
- 快捷方式指向 `ShipinCutLauncher.exe`。
- 启动器负责拉起本地 Python 服务、检查端口、打开前端页面或内置窗口。
- 优点：风险最低，能复用当前 Vite + Python 后端架构，最少触碰已稳定导出链路。
- 缺点：桌面应用体验相对朴素，后续自动更新需要单独设计。

### 方案 2：Electron 桌面壳

- 用 Electron 承载前端页面。
- 启动时拉起 Python 后端服务。
- 可做更完整的桌面窗口、托盘、自动更新、日志入口。
- 优点：桌面体验完整，生态成熟。
- 缺点：包体大，引入 Node/Electron 打包复杂度，当前阶段容易干扰刚稳定的核心链路。

### 方案 3：Tauri 桌面壳

- 用 Tauri 提供更轻量的桌面壳。
- 前端仍可复用 Vite/React。
- 优点：包体小，性能好。
- 缺点：Rust/Tauri 与 Python 服务、ffmpeg、whisper、剪映草稿路径的集成成本更高，当前项目不宜过早引入。

## 5. 推荐路线

当前阶段优先采用：Inno Setup + 本地启动器。

理由：

- 核心导出链路刚稳定，低风险优先。
- 当前项目已经是 Vite/React + Python 本地服务，安装器路线可以最大程度复用现状。
- 不需要立刻引入 Electron/Tauri 的窗口、构建、更新复杂度。
- 第一版商业化重点是让普通用户能安装、启动、输入兑换码、导出剪映草稿，而不是追求完整桌面壳。

Electron/Tauri 可以作为后续体验升级路线，不作为第一阶段打包目标。

## 6. 安装目录结构建议

建议安装目录：

```text
ShipinCut/
  app/
    frontend/
    backend/
  tools/
  runtime/
    python/
    ffmpeg/
    whisper/
  config/
  logs/
  data/
    workspace/
  ShipinCutLauncher.exe
  version.json
```

应该打进安装包：

- 前端 build 产物。
- 后端 Python 服务和必要 tools。
- Python 运行时或可复用的嵌入式环境。
- ffmpeg / ffprobe。
- whisper 运行依赖和模型文件。
- 默认配置模板。
- 启动器和版本文件。

不应该打进安装包：

- `.git/`、开发分支元数据。
- `node_modules/`。
- `export_workspace/logs/`、`tmp/`、`local-output/`、`jianying/`。
- 本地导出视频、剪映草稿、debug json。
- Codex / VS Code 附件和临时文件。

用户数据建议放到：

```text
%LOCALAPPDATA%\ShipinCut\data\
%LOCALAPPDATA%\ShipinCut\logs\
%LOCALAPPDATA%\ShipinCut\workspace\
```

安装目录只放程序和默认配置，运行数据、日志、导出工作区全部写入用户数据目录，避免污染 Git 项目目录，也避免普通用户看到复杂开发文件。

## 7. 桌面图标启动流程

`ShipinCutLauncher.exe` 点击后建议执行：

1. 检查是否已有后端服务运行。
2. 若已有服务，直接复用并打开前端。
3. 若没有服务，选择可用端口并启动本地 Python 后端。
4. 检查 `/health`，确认后端可用。
5. 检查 ffmpeg、ffprobe、whisper、模型文件、剪映草稿目录配置。
6. 检查前端静态文件是否存在。
7. 打开应用窗口或默认浏览器页面。
8. 如果端口被占用，显示中文错误并给出处理建议。
9. 如果依赖缺失，显示中文错误和缺失文件名。
10. 写入启动日志、错误日志和后端日志到 `%LOCALAPPDATA%\ShipinCut\logs\`。
11. 用锁文件或本地端口探测避免重复启动多个后端服务。
12. 关闭软件时，优先关闭由启动器拉起的后端进程；如果用户只关浏览器页，后端可短时保留或由启动器托管退出。

## 8. 后续自动更新方案

第一版不做完整自动更新，只预留：

- `version.json`：记录当前版本、构建时间、兼容的后端版本。
- 启动器检查更新接口，但默认不强制更新。
- 后续可扩展为下载增量包或完整安装包。
- 更新前备份本地配置和授权状态。
- 更新失败时回滚到上一个可用版本。

更成熟阶段可考虑 Electron/Tauri 的更新生态，或保持 Inno Setup 全量覆盖安装。

## 9. 兑换码 / 续费方案

兑换码类型建议：

- 体验码：允许导出 3 次剪映草稿。
- 月卡码：30 天内可用。
- 次数码：增加 100 次导出额度。
- 续费码：延长 30 天或增加额度。

本地保存状态：

- 用户 ID 或匿名安装 ID。
- 机器码摘要。
- 当前套餐类型。
- 到期时间。
- 剩余导出次数。
- 最近一次在线校验时间。
- 签名后的授权状态缓存。

服务端需要保存：

- 兑换码、套餐类型、额度、有效期。
- 是否已兑换、兑换时间、绑定机器码。
- 用户或客户信息。
- 使用记录和导出计数。
- 风险标记和手工冻结状态。

验证方式：

- 首次兑换必须联网。
- 服务端返回签名授权票据。
- 本地缓存只保存签名结果，不保存可直接篡改的明文额度作为唯一依据。
- 离线可短期继续使用，例如 3 天宽限。
- 超过宽限期、到期或次数用完后，禁用剪映草稿导出等核心输出功能。

本轮不实现完整后台，只设计接口和本地占位逻辑。

## 10. 管理后台未来功能

后续后台需要：

- 创建和批量生成兑换码。
- 查看兑换码状态。
- 查询用户、机器码、套餐、剩余额度。
- 查看导出次数和使用日志。
- 冻结/解冻兑换码。
- 手动增加额度或延期。
- 查看客户端版本分布。
- 发布更新和灰度策略。

## 11. 当前阶段不做事项

本阶段不做：

- 真正安装包。
- 完整自动更新。
- 完整兑换码后台。
- Electron/Tauri 大改。
- 大规模 UI 重构。
- 修改视频导入、字幕识别、组合算法。
- 修改 5333b93 的 fps/timebase/concat 导出核心逻辑。
- 修改 429368a 的 subtitle material 剪映字幕体系修复。

## 12. 分阶段实施计划

阶段 1：

- 导出成功后增加“打开草稿文件夹”按钮。
- 后端返回草稿名、草稿路径、草稿根目录、可打开路径和是否写入剪映草稿目录。
- open-path 仅允许打开剪映草稿目录、项目导出目录等安全路径。
- “尝试打开剪映”优先使用用户保存的 JianyingPro.exe / CapCut.exe 路径；再检测运行中进程、常见安装目录、开始菜单快捷方式和注册表卸载项。
- 用户手动保存的剪映路径写入 `config/local_settings.json`，该文件只保存本机配置，不进入版本控制。
- 新增安装版与商业化方案文档。

阶段 2：

- Windows 启动器雏形。
- 启动本地后端、检查依赖、打开前端页面。
- 记录启动日志。

阶段 3：

- Inno Setup 安装包。
- 安装后生成桌面快捷方式和开始菜单入口。
- 用户数据迁移到 `%LOCALAPPDATA%\ShipinCut`。

阶段 4：

- 兑换码入口 UI。
- 本地占位验证和授权状态展示。
- 到期/次数用完后禁用核心导出入口。

阶段 5：

- 兑换码后台和管理后台。
- 真实兑换、续费、额度管理、机器码绑定。

阶段 6：

- 检查更新 / 自动更新。
- 版本兼容检查、下载更新包、失败回滚。
