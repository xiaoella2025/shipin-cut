## 1. 审计目标

回答以下问题，作为 3C-2（embeddable Python POC / PyInstaller POC 备选）的输入：

## 2. 当前 3B 后端运行方式（基线）

入口（运行链路，固定不变）：

```text
桌面图标 / 开始菜单
  → {app}\启动视频混剪工具.bat
      → 调系统 Python（python.exe 在 PATH 上）
          → python tools\local_export_server.py      （主进程，8765）

                  - python tools\export_video.py                （切片 / concat）
```

`local_export_server.py` 用 `sys.executable`（当前 Python 解释器）去拉子脚本，**`local_export_server.py` 解释器版本 == `export_video.py` / `export_with_jianying.py` 解释器版本**。

后端 Python 解释器来源：系统 PATH 上的 `python.exe`。开发机实测用 `C:\Users\Admin\AppData\Local\Programs\Python\Python314\python.exe`，3C 之前并未锁定版本。

## 11. Python 版本建议

### 11.1 现状

开发机实测：`C:\Users\Admin\AppData\Local\Programs\Python\Python314\python.exe`，即 **Python 3.14**。

### 11.2 风险

- **Python 3.14 太新**：
  - `comtypes` 1.4.x 最后一个稳定版对 CPython 3.13/3.14 的支持在 1.4.5+ 才逐渐完整，vendored 的 comtypes 版本需要确认。
  - `uiautomation` 2.0.x 在 PyPI 上对 3.12+ 的官方支持要看 changelog；vendored 的 2.0.29 在 Python 3.11/3.12 上验证较多，3.14 可能边角 case。
  - `pymediainfo` 6.x 是 ctypes + MediaInfo.dll 的薄壳，理论上不挑 Python 版本，但 `importlib.metadata` 在 3.12 之后行为有微调。
  - **embeddable Python 官方目前没有 3.14 的 Windows 嵌入式包**（截至撰写时，python.org 只有 3.11/3.12/3.13 的 embeddable zip）。要走 embeddable 必须降到 3.11/3.12/3.13。

- **Python 3.12 / 3.13**：
  - 3.12 是 3C-2 当时较稳的折中。
  - 3.13 在 2026-06 已 GA，embeddable zip 已有，但**第三方 vendored 包的兼容性验证较少**。

- **Python 3.11**：
  - 生态最稳，pyJianYingDraft / pymediainfo / uiautomation / comtypes 1.x 全部官方支持。
  - embeddable zip 长期可用，体积小，**最适合走 embeddable Python 路线**。

### 11.3 推荐

**3C-2 POC 锁定 Python 3.11.x 64-bit**（具体小版本号等 POC 时看 python.org 当前 stable 选 3.11.9 ~ 3.11.13 之间）。

理由：

1. pyJianYingDraft / uiautomation / comtypes / pymediainfo 在 3.11 上是“开箱即用”状态。
2. Python 3.11 的 embeddable zip 长期稳定，路径与 `python311._pth` 配置成熟。
3. 3.11 比 3.10 性能更好（f-string parsing / exception walk 改进），且与现有开发环境（开发机是 3.14）的差异不致命，3C-2 POC 后 3C-3 启动器兼容层可以处理“3.11 vs 3.14”差异。
4. 后续 3C-3 启动器优先用 `{app}\runtime\python\python.exe`，回退到系统 PATH `python.exe`；如果系统 Python 是 3.11+/3.12+/3.13+，子脚本直接走 `sys.executable`，**回退路径对版本不敏感**。

> **不推荐在 3C 阶段升到 3.14**：3.14 解释器本身没有 embeddable 包；且 vendored 站点包对 3.14 的兼容性需要单独验证，**与 3C 目标无关**。

## 12. 3C-2 embeddable Python POC 输入清单

走方案 B（embeddable Python），需要准备：

1. **Python 3.11.x embeddable zip**：从 `https://www.python.org/ftp/python/3.11.x/python-3.11.x-embed-amd64.zip` 下载；建议从构建机离线缓存。
2. **解压位置**：`{app}\runtime\python\`（iss 阶段再固化）。
3. **pip**：embeddable 默认不带 pip；POC 阶段直接跳过 pip（不安装运行时依赖，只在构建机外部 venv 装好站点包再 copy），**安装版不带 pip**。
4. **`python311._pth` 配置**：embeddable 默认禁用 site-packages，需要在 `python311._pth` 中加入：
   ```text
   python311.zip
   .
   ..\..\tools\pyjianying_runtime      ← 让 embeddable Python 把 {app}\tools\pyjianying_runtime 当 site-packages
   import site
   ```
   也可以用 `..\..\runtime\site-packages`（如果独立放），二者选一。
5. **PYTHONPATH**：后端启动命令里**不需要**额外设 PYTHONPATH，子进程里 `import pyJianYingDraft` 命中 `..\..\tools\pyjianying_runtime`（已通过 `_pth` + `import site` 暴露）。但**保留**现有 `PYTHONPATH=tools\pyjianying_runtime` 注入逻辑作为双重保险。
6. **后端启动命令**：把 `.bat` 改为
   ```bat
   "%~dp0runtime\python\python.exe" "%~dp0tools\local_export_server.py"
   ```
   `runtime\python\` 不存在时回退到系统 `python.exe`（启动器层判断）。
7. **launcher 选择解释器优先级**（3C-3 阶段再做，本轮不实现）：
   - 优先级 1：`{app}\runtime\python\python.exe`（3C 之后的生产入口）
   - 优先级 2：系统 PATH 上的 `python.exe`（3B 当前回退；3C-2 POC 阶段保留）
   - 优先级 3：直接报错 + 提示安装 Python（3C 终态）
8. **回退机制**：runtime 缺失时 launcher 走 `python` 命令，**不**破坏 dev 流程。
9. **安装包放置**（3C-4 iss 阶段）：
   ```iss
   Source: "..\installer\runtime\python\*"; DestDir: "{app}\runtime\python"; Flags: ignoreversion recursesubdirs createallsubdirs
   ```
10. **无系统 Python 启动验证**（POC 验收）：
    - 在 Windows 沙箱里把 `PATH` 上的 `python.exe` / `python3.exe` 临时移走 / 改名。
    - 直接双击 `启动视频混剪工具.bat`（或 `runtime\python\python.exe tools\local_export_server.py`）。
    - 验证 `GET /health` 200，浏览器能打开 `/shipin-cut/`，字幕识别能跑，导出剪映草稿能跑。
    - 确认 `%LOCALAPPDATA%\ShipinCut\workspace` 有新文件，`{app}` 没有任何新写入。

## 13. 3C-2 PyInstaller POC 备选清单

如果 3C-2 embeddable POC 暴露隐藏坑（典型：`python311._pth` 与 `import site` 行为异常、`pip` 缺失导致自检脚本跑不起来、`subprocess` 在 embeddable 下遇到 `os.path.dirname(__file__)` 解析异常），切到 PyInstaller POC。

需要准备：

1. **`shipin_cut_backend.spec`**：明确 `entry=[tools/local_export_server.py]`（不打包 export_video / export_with_jianying 子脚本——继续以 `.py` 形式由主进程 `subprocess` 拉）。
2. **`hiddenimports`**：
   - `pyJianYingDraft`（即便我们只 import 子集，`__init__.py` 顶层也会触发 `jianying_controller`，所以**必须**显式列出）
   - `pyJianYingDraft.jianying_controller`
   - `uiautomation`
   - `uiautomation.uiautomation`（`from .uiautomation import *`）
   - `comtypes`
   - `comtypes.client`
   - `comtypes.client._code_cache` / `_constants` / `_create` / `_events` / `_generate` / `_managing` / `dynamic` / `lazybind`
   - `winreg`（PyInstaller 树摇要 `--collect-all winreg` 或 `--hidden-import winreg`）
   - `pymediainfo` 全部子模块
3. **`datas`**：
   - `('tools/pyjianying_runtime', 'pyjianying_runtime')`（保留目录结构）
4. **`binaries`**：
   - `('tools/pyjianying_runtime/pymediainfo/MediaInfo.dll', '.')` —— **这是最容易漏的**，MediaInfo.dll 必须打进 exe 同级或 `pymediainfo` 解析的目录。
5. **pyJianYingDraft runtime**：随 `datas` 一起打入。
6. **ffmpeg / whisper 外部资源**：不进 exe 也不进 `_MEIPASS`，**保留**当前 `{app}\local-tools\ffmpeg\` 与 `{app}\tools\whisper\` 的目录结构；`--add-data` 也不要碰它们（它们是独立工具链，由后端 `_find_local_tool` 命中）。
7. **LocalAppData 路径策略**：`resolve_writable_paths` 已经在 `local_export_server.py` 写好，**PyInstaller 模式下完全不变**，exe 仍然从 `{app}` 读、`%LOCALAPPDATA%` 写。
8. **杀毒误报风险说明**（写入 3C-2 交付物）：
   - PyInstaller 加壳产物在 Windows Defender / 360 / 火绒 上有一定概率被误报。
   - 缓解：代码签名（需要 EV 证书，成本高）、白名单说明、给内部测试机批量加信任。
   - 当前阶段建议**先试 embeddable**，**只**在 embeddable 明显不合适时再切 PyInstaller。

## 14. 风险点汇总

- **打包体积**：
  - embeddable Python 3.11：~10 MB（python311.zip + 解释器 dll）。
  - site-packages（pyJianYingDraft + pymediainfo + uiautomation + comtypes）：~14 MB（其中 MediaInfo.dll 7.5 MB）。
  - 合计 +24 MB。`installer\dist\ShipinCutSetup.exe` 当前（v0.9.13）以 LZMA 压缩后约 30 MB 左右（粗估，含 dist + tools + whisper + 142 MB 模型）；3C 之后会涨到 ~50 MB。
  - whisper 模型（142 MB）要不要进安装包要单独决策，**本轮不展开**。

- **杀毒误报**：
  - embeddable Python 低（无加壳）。
  - PyInstaller 中等。
  - Inno Setup 本身已被主流杀软信任，影响不大。

- **Windows 路径空格 / 中文**：
  - `{app}` 在用户机器可能是 `C:\Program Files\ShipinCut`（含空格）或 `D:\工具\视频混剪`（含中文）。
  - 所有 `subprocess.run([...])` 都已是 list 形式（不拼字符串），**没有** shell=True，**安全**。
  - embeddable Python 解释器路径也用 `%~dp0runtime\python\python.exe`（bat 里的 `%~dp0` 自动 quote）。
  - `python311._pth` 里如果写死绝对路径就破——**保持相对路径**（`..\..\tools\pyjianying_runtime`）。

- **`MediaInfo.dll` 找不到**：
  - 必须在 `pymediainfo/` 同目录，**已正确**。
  - embeddable 下 ctypes.WinDLL 行为与系统 Python 一致，**不会**额外出问题。
  - PyInstaller 下如果 `binaries` 没把 `MediaInfo.dll` 放到正确位置，会爆；spec 写对就行。

- **pyJianYingDraft import 路径**：
  - 当前用 `PYTHONPATH=tools\pyjianying_runtime` 显式注入。
  - 3C embeddable 路线下用 `python311._pth` + `import site` 暴露，**双重保险**保留 PYTHONPATH 注入。
  - 3C PyInstaller 路线下用 `--add-data` 复制到 `_MEIPASS/pyjianying_runtime`，**不需要** PYTHONPATH（PyInstaller 会自动加）。

- **whisper / ffmpeg 路径**：
  - 3B 已经有 `_find_local_tool` 兜底。
  - 3C 不要改 `_find_local_tool` 的命中顺序。
  - whisper 模型 142 MB 要不要进安装包单独决策（建议默认进，但允许用户在安装向导选“跳过模型”以减小安装包；**3C 不实现**这个选项）。

- **剪映草稿目录权限**：
  - 写 `%LOCALAPPDATA%` 不需要管理员，**3C 不要把剪映草稿写回 `{app}`**。

- **用户目录数据迁移**：
  - 3B 已经把数据写 `%LOCALAPPDATA%\ShipinCut\…`。
  - 3C 不需要做迁移，**不要**改 `resolve_writable_paths`。

- **开发态 vs 安装态**：
  - 启动器在仓库根运行时仍要继续 work（开发态用系统 Python 跑）。
  - 3C 不要把开发态也强制走 `{app}\runtime\python`。

- **升级路径**：
  - embeddable Python 升级到 3.12 时，要重新构建 `{app}\runtime\python\` 整目录，依赖也要重新安装到新版 `Lib\site-packages`。
  - 升级时建议在 `installer/README.md` 文档化 “升级 Python → 重新跑 bootstrap 脚本 → 重打安装包” 流程。

## 15. 3C-2 推荐路线

**优先做方案 B（embeddable Python 3.11.x 64-bit）POC，方案 A（PyInstaller）作为 3C-2 备选**。

理由：

1. 改动面最小：只把 `.bat` 里的 `python` 改为 `{app}\runtime\python\python.exe`，主进程 + 子脚本链路零修改。
2. 调试 / 升级透明：`runtime\python\` 目录里就是普通 `python.exe` + `Lib\site-packages`，出问题能直接 `python -c "import pyJianYingDraft"` 排错。
3. 杀毒误报显著低于 PyInstaller。
4. 主进程打包（PyInstaller 方案 A）会把子脚本链路变成“exe 拉 py 拉 ffmpeg”，跨进程调试比“py 拉 py 拉 ffmpeg”复杂。
5. embeddable POC 暴露坑再切 PyInstaller，**不浪费**前期准备。

**POC 通过条件**（与 3C 方案文档第 6 节一致，详见 `docs/阶段3C-Python运行时打包方案-20260620.md`）：

- 沙箱里把系统 `python.exe` 临时移走，后端仍能启动并响应 `GET /health`。
- 浏览器能打开 `/shipin-cut/`。
- 字幕识别能跑（whisper 路径未变）。
- 导出剪映草稿能跑（pyJianYingDraft 路径通过 `python311._pth` 暴露）。
- `{app}` 无运行时写入。
