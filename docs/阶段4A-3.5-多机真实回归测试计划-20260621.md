## 4. 测试前不要做

> 这一节是给测试人的**强约束**，防止测试环境被污染。

**不要**提前安装：

- ❌ Python（任何版本，包括 3.11 / 3.12 / 3.13 / 嵌入式）
- ❌ Node.js / npm
- ❌ ffmpeg / ffprobe
- ❌ whisper-cli / whisper.cpp / ggml-base.bin
- ❌ Git
- ❌ VS Code / PyCharm / 任何 IDE
- ❌ Anaconda / Miniconda / venv

**不要**手动拷贝：

- ❌ 不要从开发机把 `runtime\python\` 拷到测试机
- ❌ 不要从开发机把 `tools\whisper\` 拷到测试机
- ❌ 不要从开发机把 `local-tools\ffmpeg\` 拷到测试机
- ❌ 不要从开发机把 `tools\pyjianying_runtime\` 拷到测试机

**不要**改环境：

- ❌ 不要改 `%PATH%` 环境变量
- ❌ 不要设 `PYTHONPATH` / `PYTHONHOME`
- ❌ 不要设 `SHIPIN_CUT_DATA_ROOT` / `SHIPIN_CUT_PORT`
- ❌ 不要装 Windows 子系统（WSL）
- ❌ 不要启 Windows Sandbox

**剪映的处理**：

- ✅ **如果**电脑已有剪映专业版，**可以**用来测"剪映能否看到导出的草稿"
- ✅ **如果**电脑没装剪映，**可以**装一个（剪映是 4A 阶段**不**包含的外部依赖，由用户自行装）
- ⚠️ 装剪映要在测试记录表里**标注**"测试前是否已有剪映"——这会影响"草稿能否被剪映识别"的判断（没装剪映 = 无法验证剪映识别，只验证草稿文件齐全）

**为什么有这些约束**：

- 我们的演示包**自带** Python / whisper / ffmpeg / pyJianYingDraft 运行时，**不**依赖系统 PATH
- 如果测试机**已经**装了 Python / Node，后端会优先用 `{app}\runtime\python\python.exe`（验证方法见 §7 C 节）
- 但**提前装**会让"是不是真的不依赖系统 X"的判断变得模糊，所以**最好是干净**
- 如果测的是"已经开发过的同事的电脑"，就**不**算严格干净机，需要在备注里说明

## 6. 每台电脑安装步骤

> 这一节是给测试人的**小白步骤**，按顺序做，不要跳。

### 6.1 安装前（5 分钟）

1. **截图保存**：把桌面截图存一份（之后用作"对比安装前后"）
2. **检查任务管理器 → 进程**：看是否有 python.exe / node.exe 在跑（应该没有）
3. **打开 PowerShell 跑以下命令**（验证干净）：

   ```powershell
   # 验证 Python 是否装
   python --version 2>&1
   # 验证 Node 是否装
   node --version 2>&1
   # 验证 ffmpeg 是否装
   ffmpeg -version 2>&1
   # 验证剪映是否装（可选）
   Test-Path 'C:\Program Files\JianyingPro\JianyingPro.exe'
   ```

4. **记录以上命令的输出**到测试记录表（哪怕是"未识别命令"）

### 6.2 安装（5 分钟）

1. **双击** `ShipinCutSetup.exe`
2. **UAC 弹窗**（用户账户控制）→ 选择"**是**"
3. **Inno Setup 向导** → 选"下一步"
4. **选择安装位置**：
   - 默认 `C:\Program Files\ShipinCut`（含空格，OK）
   - 可以改成 `D:\ShipinCut\` 或 `C:\ShipinCutTest\`（避免 Program Files 权限问题）
   - ⚠️ **不要**装到 OneDrive / 网盘同步目录
5. **下一步** → **下一步** → **安装** → 等 30–60 秒
6. **完成**："Installation was successful"
7. **勾选**"安装完成后启动视频混剪工具"（可选）

### 6.3 启动（1 分钟）

1. **看桌面**：应该有"视频混剪工具"快捷方式
2. **双击桌面图标**
3. **等 5–10 秒**：首次启动会编译部分 `.pyc` 到 `%LOCALAPPDATA%\ShipinCut\cache\pycache\`
4. **浏览器自动打开**：地址栏应该是 `http://127.0.0.1:8765/shipin-cut/`
5. **检查页面**：应该看到工具主页（上传区 / 字幕列表 / 预览区 / 顶部 header 含激活徽章）

### 6.4 安装后核对（2 分钟）

1. **打开文件资源管理器** → `C:\Program Files\ShipinCut\`（或自定义路径）
2. **核对**以下文件 / 目录存在：

   ```
   runtime\python\python.exe        (~20 MB)
   tools\whisper\whisper-cli.exe    (~486 KB)
   tools\whisper\models\ggml-base.bin  (~141 MB)
   local-tools\ffmpeg\ffmpeg.exe    (~100 MB)
   local-tools\ffmpeg\ffprobe.exe   (~100 MB)
   tools\pyjianying_runtime\        （多个子目录）
   dist\index.html                  （前端入口）
   launcher\ShipinCutLauncher.py    （启动器）
   ```

3. **核对**安装目录**没有**以下子目录（运行时不会写安装目录）：

   ```
   ❌ logs\
   ❌ config\
   ❌ cache\
   ❌ workspace\
   ❌ export_workspace\
   ❌ tmp\
   ❌ temp\
   ```

4. **打开 `%LOCALAPPDATA%\ShipinCut\`** → 应该有：

   ```
   cache\pycache\        （.pyc 文件，可能有几十个）
   logs\launcher\        （启动器日志）
   logs\backend\         （后端日志）
   workspace\videos\     （空，等用户上传）
   config\               （空，等用户激活）
   ```

### 6.5 关键约束

- ❌ **不要手动打开 5173**（开发环境端口，安装版不用）
- ❌ **不要在 cmd 里手动敲 `python` / `node`**（会被系统 PATH 上的同名工具误导）
- ❌ **不要在安装目录里手动建任何子目录**
- ✅ **可以**多次重启 launcher（关掉黑窗口 → 双击桌面图标）

### 7.C 环境依赖测试

> 这一节是**最重要**的——验证"安装版不依赖系统 Python / Node / ffmpeg / whisper"。

**在 PowerShell 里跑**（在测试机的 PowerShell，不是开发机）：

```powershell
# 1. 确认系统 Python 没装（或装了也不用）
python --version 2>&1
where.exe python 2>&1
python3 --version 2>&1
py --version 2>&1

# 2. 确认 Node 没装（或装了也不用）
node --version 2>&1
where.exe node 2>&1
npm --version 2>&1

# 3. 确认 ffmpeg 没装（或装了也不用）
ffmpeg -version 2>&1
where.exe ffmpeg 2>&1

# 4. 确认 whisper 没装
whisper-cli --help 2>&1
where.exe whisper-cli 2>&1

# 5. 验证后端用的是 embedded python
Get-Process -Name python -ErrorAction SilentlyContinue |
  Select-Object Id, Path | Format-Table -AutoSize
# ↑ Path 应该指向 {app}\runtime\python\python.exe，不是系统 Python
```

**通过标准**：

- ✅ `python` / `node` / `ffmpeg` / `whisper-cli` 命令**找不到**（输出 "不是内部或外部命令"），但**工具仍能启动**
- ✅ `Get-Process python` 的 `Path` 指向 `{app}\runtime\python\python.exe`，**不是** `C:\Users\...\.venv\python.exe` 或 `C:\Python311\python.exe`
- ✅ 浏览器页面正常显示

**关键判定**：哪怕系统**装**了 Python / Node，工具仍然**只用** `{app}\runtime\python\python.exe`，**不**回退到系统 PATH 上的工具。

## 9. 失败处理规则

> 这一节是"如果某台电脑失败"的标准处理流程。**核心原则：先收集信息，不要现场乱装依赖。**

### 9.1 立即要做

**截图收集**：

- [ ] 安装向导报错截图（如果安装失败）
- [ ] 黑窗口截图（如果启动失败）
- [ ] 浏览器页面截图（如果页面异常）
- [ ] 杀毒软件拦截弹窗截图（如果被拦截）
- [ ] 任务管理器 → 进程截图（看 python.exe / node.exe 是否在跑）

**日志收集**：

- [ ] `%LOCALAPPDATA%\ShipinCut\logs\launcher\` 下最新日志 → 整个文件复制
- [ ] `%LOCALAPPDATA%\ShipinCut\logs\backend\` 下最新日志 → 整个文件复制
- [ ] 任务管理器 → 详细信息 → `python.exe` 右键 → 属性 → 看 exe 路径

**环境信息**：

- [ ] Windows 版本（`Win+R` → `winver`）
- [ ] 用户名（中文 / 英文 / 含空格）
- [ ] 安装路径
- [ ] 是否有剪映（版本）
- [ ] 是否有 Python / Node（`where.exe python` / `where.exe node`）

### 9.2 **不要**做的事

- ❌ **不要**现场装 Python（哪怕"看起来少装了"）
- ❌ **不要**现场装 Node.js
- ❌ **不要**现场把 `runtime\python\` 从开发机拷过来
- ❌ **不要**改 `%PATH%` 环境变量
- ❌ **不要**用杀毒软件的"信任"按钮（除非是 Windows Defender 已知误报）
- ❌ **不要**反复重装（先看一次日志，搞清楚失败原因再决定是否重装）
- ❌ **不要**自行改安装目录里的 `.py` 文件

### 9.3 信息回传

把以下内容**打包**（zip / 网盘）发给开发机分析：

```
机器号-A_失败信息.zip
├── 截图/
│   ├── 安装报错.png
│   ├── 黑窗口.png
│   ├── 页面.png
│   ├── 杀软拦截.png
│   └── 任务管理器.png
├── logs/
│   ├── launcher_20260621.log
│   └── backend_20260621.log
├── 环境信息.txt              (Windows 版本 + 用户名 + 安装路径 + 是否有剪映/Python/Node)
└── 复现步骤.md               (从头到尾做了什么、看到了什么)
```

然后回到开发机，分析失败原因，**不**要在测试机上乱改环境。

### 9.4 失败原因分类（开发机分析时用）

| 类别 | 例子 | 处理 |
|---|---|---|
| **环境差异** | Win10 家庭版 vs 专业版差异、用户名含中文、磁盘权限 | 调整安装路径 / 改 launcher 处理中文路径 |
| **杀毒软件** | Windows Defender / 360 / 火绒误报 | 走白名单 / 提交厂商 |
| **依赖冲突** | 系统装了旧版 Python / Node，路径冲突 | launcher 优先级已经写死，但仍要确认 |
| **剪映版本差异** | 剪映 6+ 改了草稿格式 | pyJianYingDraft 适配（**后续阶段**） |
| **真实代码 bug** | 任何 ERROR / Traceback / 0 段字幕 | 复现 → 修代码 → 重打安装包（**不**是本轮做的） |
| **硬件差异** | 无独立显卡 / ARM CPU / 32 位 | 当前不支持，需要后续适配 |
