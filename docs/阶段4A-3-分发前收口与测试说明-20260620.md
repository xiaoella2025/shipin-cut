## 7. 常见问题 FAQ

### Q1：为什么安装包这么大（190 MB）？

A：安装包内置了完整的运行时，不依赖用户电脑装任何东西：

- embedded Python 3.11.9 约 20 MB
- whisper-cli + ggml-base.bin 中文模型约 141 MB（模型是字幕识别的核心，必须随包）
- ffmpeg + ffprobe 约 200 MB
- pyJianYingDraft + pymediainfo + uiautomation + comtypes 约 30 MB
- 前端 dist/ 约 1 MB
- 后端 / launcher / 文档约 5 MB

实际解压到硬盘约 600 MB（含 LZMA 解压后体积）。如果想瘦身，可以后续做差分下载（5A 自动更新阶段），但当前先把功能跑通。

### Q2：需要装 Python 吗？

A：**不需要**。v0.5.1 安装包自带 Python 3.11.9（embedded 发行版），位于安装目录下的 `runtime\python\python.exe`，启动器优先用它。

### Q3：需要装 Node / npm 吗？

A：**不需要**。前端在 3B 阶段已经静态化，由 Python 后端（8765）直接托管 `dist/`，不依赖 Vite dev server。

### Q4：页面为什么是 `http://127.0.0.1:8765`？

A：这是**本机**服务地址。工具在自己电脑上运行（一个本地 HTTP 服务），不是公开网站。`127.0.0.1` 是"本机回环"地址，浏览器只能从这台电脑访问。**不**会暴露到公网。

### Q5：为什么是 8765，不是 5173？

A：5173 是开发环境的 Vite dev server 端口（开发态用 `npm run dev` 时启动）。**安装版从 3B 起已经改成 8765**——前端静态化后由 Python 后端直接托管，**不**启动 Vite，也**不**用 5173。开发态如果要本地实时改前端，可以单独跑 `npm run dev`（5173），与安装版互不干扰。

### Q6：兑换码是真的吗？能用 `SHIPIN-TEST-2026` 激活吗？

A：当前是**本地演示码**，用于测试入口；**不**是真实授权。激活状态**只**保存在本机 `%LOCALAPPDATA%\ShipinCut\config\activation.json`，**不**联网、**不**校验、**不**绑机器。真实授权后台会在 4B 阶段接入。

### Q7：测试兑换码是什么？

A：当前 3 个本地测试码（写死在 `tools\local_export_server.py:ACTIVATION_TEST_CODES`）：

```
SHIPIN-TEST-2026
SHIPIN-VIP-LOCAL
MIXCUT-LOCAL-OK
```

任意一个都能激活。其它任何字符串都会返回"兑换码无效，当前仍可继续试用"，**不**影响使用。

### Q8：字幕识别失败怎么办？

A：先按以下顺序排查：

1. **换一个短视频测试**：建议 30 秒内、含清晰人声、mp4 格式
2. **检查上传的视频是否完整**：用本地播放器能播
3. **看后端日志**：`%LOCALAPPDATA%\ShipinCut\logs\backend\` 下最新日志，找 ERROR 行
4. **看启动器日志**：`%LOCALAPPDATA%\ShipinCut\logs\launcher\` 下最新日志
5. **检查安装目录**：`{app}\tools\whisper\whisper-cli.exe` 和 `{app}\tools\whisper\models\ggml-base.bin` 是否存在

如果以上都正常仍失败，把日志贴给助理。

### Q9：剪映草稿导出后在哪里？

A：导出成功后工具会弹提示"打开草稿文件夹"，点开后是剪映的本地草稿目录：

```
%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\<draft-name>\
  draft_content.json
  draft_meta_info.json
  draft_settings
  timeline_layout.json
```

打开剪映 → 我的草稿 → 找到对应的草稿名 → 拖到时间线即可。如果剪映里看不到，刷新一下剪映草稿列表，或重启剪映。

### Q10：运行数据（视频 / 日志 / 缓存）在哪？

A：全部在 `%LOCALAPPDATA%\ShipinCut\` 下：

```
%LOCALAPPDATA%\ShipinCut\
├── logs\
│   ├── launcher\               （启动器日志）
│   └── backend\                （后端日志）
├── runtime\                    （启动锁、运行期状态）
├── config\
│   └── activation.json         （4A 激活状态）
├── cache\
│   └── pycache\                （embedded Python 的 .pyc 缓存）
└── workspace\
    ├── videos\                 （用户上传的视频）
    ├── temp\                   （处理中临时文件）
    ├── output\                 （处理后的视频片段）
    └── drafts\                 （剪映草稿中间产物）
```

**安装目录（`{app}`）只放程序文件，运行时不会写它**。

### Q11：可以装在 D 盘 / 中文目录 / 含空格的目录吗？

A：可以。Inno Setup 用 list 形式调用 `subprocess`，所有路径都做了 quote。**不**要装到 OneDrive / 网盘同步目录下。

### Q12：可以覆盖安装 / 升级吗？

A：当前 v0.5.1 的覆盖安装已验证 OK。后续做自动更新（5A 阶段）时，会先关后端再覆盖 `{app}\runtime\python\`（约 20 MB），不要在运行时直接覆盖。

### Q13：可以卸载吗？

A：可以。控制面板 → 程序和功能 → 视频混剪工具 → 卸载。**注意**：卸载会保留 `%LOCALAPPDATA%\ShipinCut\`（用户数据 / 草稿 / 缓存），如要彻底清理请手动删除。

### Q14：可以离线用吗？

A：可以。v0.5.1 完全离线运行，**不**做远程校验 / 心跳 / 自动更新（这些会在 4B / 5A 阶段加入）。

### Q15：杀毒软件报毒怎么办？

A：v0.5.1 在本机 Windows Defender 默认策略下能直接放行。**未做**主流杀软（360 / 火绒 / 卡巴斯基）的长期观察，遇到误报请把安装包提交给对应厂商做白名单申请。**不要自行删除安装目录**，否则需要重装。后续 4B / 5A 阶段准备安装包签名（Authenticode）会降低误报概率。

## 11. 关于安装目录残留 `__pycache__\` 目录的说明

> 4A-2 PATH 隔离测试发现：安装目录有 12 个空 `__pycache__\` 目录，**没有**任何 `.pyc` 文件。本节说明这个现象 + 本轮为什么**不**修 + 后续怎么修。

### 11.1 现象

`{app}\` 下有 12 个空 `__pycache__\` 占位目录（4A-2 实测）：

- `{app}\launcher\__pycache__\`
- `{app}\tools\pyjianying_runtime\comtypes\__pycache__\`
- `{app}\tools\pyjianying_runtime\comtypes\client\__pycache__\`
- `{app}\tools\pyjianying_runtime\comtypes\gen\__pycache__\`
- `{app}\tools\pyjianying_runtime\comtypes\tools\__pycache__\`
- `{app}\tools\pyjianying_runtime\comtypes\tools\codegenerator\__pycache__\`
- `{app}\tools\pyjianying_runtime\comtypes\_post_coinit\__pycache__\`
- `{app}\tools\pyjianying_runtime\pyJianYingDraft\__pycache__\`
- `{app}\tools\pyjianying_runtime\pyJianYingDraft\assets\__pycache__\`
- `{app}\tools\pyjianying_runtime\pyJianYingDraft\metadata\__pycache__\`
- `{app}\tools\pyjianying_runtime\pymediainfo\__pycache__\`
- `{app}\tools\pyjianying_runtime\uiautomation\__pycache__\`

### 11.2 性质

- ✅ **不是运行时写入 bug**：所有 12 个目录的 `CreationTime` 都是 Inno Setup 安装时间戳（4A-2 实测 `2026/6/21 16:24:46`），**不是** launcher 启动时间
- ✅ **不包含 `.pyc` 文件**：`Get-ChildItem -Recurse -Filter '*.pyc'` 在 `{app}` 下返回 **0** 个文件
- ✅ **不影响功能**：字幕识别 / 剪映草稿导出 / 激活入口全部正常
- ✅ **运行时字节码全部走 LocalAppData**：`%LOCALAPPDATA%\ShipinCut\cache\pycache\` 有 87 个 `.pyc` 文件（4A-2 实测）

### 11.3 原因

- vendored packages（`comtypes\` / `pyJianYingDraft\` / `pymediainfo\` / `uiautomation\`）从源仓库拷到 `tools\pyjianying_runtime\` 时，**已包含**这些空 `__pycache__\` 目录（vendored 包在源端就 strip 不干净）
- Inno Setup `Excludes: "__pycache__\*,*.pyc"` 只能排除**文件**匹配 `__pycache__\*`（实际是匹配 `__pycache__/<anything>` 路径下的文件），**不**能排除**目录**本身
- Inno Setup 的 `Flags: recursesubdirs createallsubdirs` 会保留所有子目录结构

### 11.4 本轮为什么**不**修

- 修这个需要给 `installer\shipin-cut.iss` 加 Pascal Script `[Code]` 段（`CurStepChanged(ssPostInstall)` 时递归删除空 `__pycache__\`），**会**增加安装包复杂度
- 当前阶段已经**功能上**干净（无 `.pyc`），只有**结构上**残留 12 个空目录
- 用户在 §4 / §5.8 已被告知"这是预期行为，**不**算 bug"
- 本轮重点是"分发前可读、可测、可解释"，不是继续扩功能（用户原话）
- 用户明确允许"如果 Inno Setup 递归删除空目录实现麻烦，本轮可以只在文档里记录，不强行修"

### 11.5 后续怎么修（4A-4 或 5A 阶段再做）

候选方案：

- **方案 1**：在 `installer\shipin-cut.iss` 加 `[Code]` Pascal Script，`CurStepChanged(ssPostInstall)` 时递归删除 `{app}` 下所有空 `__pycache__\` 目录
- **方案 2**：在 vendored packages 拷到 `tools\pyjianying_runtime\` 前先 strip（修改 `tools\pyjianying_runtime\` 的 sync 流程）
- **方案 3**：用 `[UninstallDelete]` 段在卸载时清，但**不**解决"安装时就有"的现状
- **方案 4**：直接换 Inno Setup 版本 / 换打包工具（如 NSIS / Advanced Installer），**不**推荐（成本太高）

**建议优先方案 1**，**预计**新增 ~15 行 Pascal Script，**需要**重打安装包 + 重做安装版冒烟测试。

### 11.6 临时应对

如果助理 / 学员看到这 12 个目录觉得不舒服：

- ✅ 可以**忽略**（功能不受影响）
- ✅ 可以**手动删除**（`Remove-Item -LiteralPath '{app}\path\__pycache__' -Recurse -Force`），运行时 `PYTHONPYCACHEPREFIX` 会重新生成
- ❌ **不**要删整个 `tools\pyjianying_runtime\`（会破剪映草稿导出）
