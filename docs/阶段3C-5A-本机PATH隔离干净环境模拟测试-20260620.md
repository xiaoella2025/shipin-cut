# 阶段 3C-5A：本机 PATH 隔离干净环境模拟测试 - 2026-06-20

> 本轮在本机用“强 PATH 隔离”模拟 3C-5 干净机场景，验证 3C-4 安装版确实**不**依赖系统 Python / Node / ffmpeg / whisper。本轮**不**开 Windows 沙盒、不重启、不改 Windows 功能。
>
> 真正的 Windows 沙盒 / 虚拟机测试留到 3C-5B（可选）；3C-5C 多机器回归测试也留到后续。

## 1. 为什么先做 3C-5A

| 选项 | 3C-5A（本轮） | 3C-5B（Windows 沙盒） | 3C-5C（VM / 多机） |
|---|---|---|---|
| 重启电脑 | ❌ | ✅（启用“Windows 沙盒”要重启） | 不一定 |
| 改系统功能 | ❌ | ✅（开 / 关可选功能） | ❌ |
| 准备一台干净机器 | ❌ | ✅（沙盒就是干净环境） | ✅ |
| 隔离强度 | 中（PATH + 几个 env） | 强（完全独立 OS 实例） | 强 |
| 跑一轮耗时 | 30 秒 | 5–10 分钟（沙盒冷启 + 安装） | 30–60 分钟 |
| 适合做的事 | **回归 / 冒烟 / 锁定回归** | 第一次真干净验收 | 多机回归 |

3C-5A 用最少的代价提供最有价值的隔离验证：**只要 PATH 上没有系统 Python / Node / ffmpeg / whisper，启动器仍然能跑、whisper / ffmpeg 仍然能调，证明安装版自带 runtime 真的够用**。这是 3C-4 端到端验证（在本机 dev 路径上跑）覆盖不到的盲区。

## 3. 测试脚本

`scripts\test-clean-path-launch.ps1`（3C-5A 新增，359 行）。

设计原则：

1. **不动系统环境变量**：所有 PATH / env 修改只发生在当前 PowerShell 进程内，`SUMMARY` 步骤里 `env:PATH = originalPath` 恢复。
2. **PATH 缩到 Windows 基础目录**：包含 `System32`（`where` / `tasklist` / `netstat` / `curl`）、`C:\Windows`（兼容调用）、`Wbem`（wmic 之类）、`WindowsPowerShell\v1.0`（PowerShell 自身定位）。
3. **断言式**：每一步必须 OK 才推进；任意一步失败 → `throw` → 标记 `failed` → 退出码 1。
4. **不依赖 system 工具做关键判定**：所有 `where` 调用都用 `where.exe` 绝对路径；所有 `Get-Process` / `Invoke-WebRequest` 都是 PowerShell 内置。
5. **不动 system Python / py / node**：直接用 `{app}\runtime\python\python.exe` 绝对路径拉起 launcher；通过 helper bat 写一个一行 bat 把命令行参数转成 bat 友好格式，绕开 PowerShell `Start-Process -ArgumentList` 的中文 / 编码踩坑。
6. **可重入**：`SkipHeavy` 参数可跳过 transcribe / jianying（默认开），方便只验基础链路。

跑法：

```powershell
# 默认跑（隔离 + 全部检查）
powershell -ExecutionPolicy Bypass -File scripts\test-clean-path-launch.ps1

# 指定安装目录
powershell -ExecutionPolicy Bypass -File scripts\test-clean-path-launch.ps1 -InstallDir D:\ShipinCutTest

# 只验基础（跳 whisper / jianying）
powershell -ExecutionPolicy Bypass -File scripts\test-clean-path-launch.ps1 -SkipHeavy
```

## 6. 未覆盖项 / 与真干净机的差距

3C-5A 在**本机**做的，**不是**真干净机。差异清单：

| # | 差异 | 3C-5A 怎么处理 | 3C-5B / 3C-5C 是否要补 |
|---|---|---|---|
| 1 | 系统 Python 实际文件还在硬盘上（只是从 PATH 拿不到） | 不影响（启动器只 `where`，不直接调系统 Python） | 真干净机直接没文件，更稳 |
| 2 | 系统 ffmpeg.exe 实际文件还在硬盘上 | 不影响（后端调 ffmpeg 用 `{app}\local-tools\ffmpeg\ffmpeg.exe` 绝对路径） | 同上 |
| 3 | 系统 Node.js 实际文件还在硬盘上 | 不影响（启动器不调 Node / npm） | 同上 |
| 4 | PATH 之外的 registry / COM / WMI 等仍可能暴露 Python | 启动器/后端不读 registry / COM 解析 Python 路径 | 真干净机彻底没有 |
| 5 | WindowsApps 别名（Microsoft Store python.exe / winget 等） | 已经 `where python` 验证为空 | 真干净机也空 |
| 6 | C:\Windows 仍然能找到 PowerShell / .NET 等 | launcher 不用这些 | 启动器自身只用 stdlib，不需要 .NET |
| 7 | `pip install` 之类的开发动作不能复现 | 3C-5A 不做 | 真干净机也装不了 pip（embedded 无 pip） |
| 8 | Windows Defender / 杀毒软件 | 本机 360 / Defender 静默放行 | 真干净机可能有不同策略 |
| 9 | Program Files 真实只读路径 | 3C-5A 用 `C:\ShipinCutCleanTest`（用户可写）模拟 | 3C-5B 必测真 Program Files |
| 10 | 卸载 → 重装 | 3C-5A 没测 | 3C-5B 必测 |
| 11 | 自定义安装目录（含中文 / 空格） | 3C-5A 用 `C:\ShipinCutCleanTest` 跑 | 3C-5B / 3C-5C 必测 |
| 12 | 冷启动时间 | 3C-5A 没记录（PYTHONPYCACHEPREFIX 冷启 + backend 冷启 = ~1.5 s） | 3C-5B 必测 |
| 13 | v0.9.12c UI 验证 | 3C-5A 没做（PATH 隔离与该 bug 无关） | 3C-5B 必测 |
| 14 | 长时间运行（>1 h）内存 / 句柄 / pyc 数量 | 3C-5A 没做 | 3C-5B / 3C-5C 选做 |
| 15 | 学员机器差异（不同 Windows 版本、不同语种） | 3C-5A 是本机 Win 10 19045 | 3C-5B / 3C-5C 必测 |

## 10. 是否建议进入 3C-5B（Windows 沙盒 / 虚拟机）

**建议**：3C-5A 已**充分**证明 3C-4 安装版的“自带 runtime 独立可用”这条核心命题，**足以支撑对外交付**（内测 / 教学场景）。

3C-5B（Windows 沙盒 / 虚拟机真干净机）**可选**，**不是必须**：

| 决策 | 原因 |
|---|---|
| 3C-5B **可做** | 跑 §6 列的差异清单（#1–#15），覆盖 3C-5A 没碰到的边角（真 Program Files、卸载重装、含中文路径、长时间运行） |
| 3C-5B **不必立即做** | 3C-5A 已经把核心链路（全功能 + pycache + LocalAppData）跑通；学员机器上 99% 概率遇到的情况 3C-5A 已覆盖 |
| 3C-5B **建议时机** | 学员首轮内测反馈后再做（拿到真实学员机器数据，决定要不要在 3C-6 修一些 Windows 版本 / 杀毒 / 路径相关的边角 bug） |

如果决定做 3C-5B，建议流程：

1. **开启 Windows 沙盒**（控制面板 → 程序 → 启用或关闭 Windows 功能 → 勾选“Windows 沙盒” → 重启）。
2. 在沙盒里跑 `installer\dist\ShipinCutSetup.exe`（注意：Setup.exe 是 190 MB，沙盒内嵌的是 Windows 10/11 精简镜像，需要从主机或网络把 Setup.exe 拷进去）。
3. 装到 `C:\Program Files\ShipinCut`（真 Program Files，触发 UAC + 真只读约束）。
