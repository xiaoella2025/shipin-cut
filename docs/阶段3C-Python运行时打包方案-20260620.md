# 阶段 3C：Python 运行时打包方案 - 2026-06-20

> 本轮仅做方案与任务拆解。**本轮不直接改 launcher、不直接上 PyInstaller、不直接改安装包主逻辑。**

## 1. 阶段背景

阶段 3B 已通过：安装版不再需要 Node / npm，前端由后端 8765 托管 `dist/` 静态资源，桌面图标点击后浏览器进入 `http://127.0.0.1:8765/shipin-cut/`。

但 3B 的运行入口仍然是：

```bat
{app}\启动视频混剪工具.bat
    → 调系统 Python
        → python tools\local_export_server.py
            → 8765
```

要求用户电脑已经装好 Python（解释器本身），对内测人员 OK，对“普通学员”仍不达标。

阶段 3C 目标：**用户不需要安装 Python**，安装包自带后端运行环境，桌面图标点击直接可用。

## 2. 当前 Python 依赖现状（依赖清单审计入口）

后端 Python 进程 / 子进程链路：

- `tools/local_export_server.py`（主进程，std HTTPServer）。
- `tools/export_video.py`（子进程，被 `local_export_server.py` 用 `subprocess` 调起，负责切片 / concat / 音视频处理）。
- `tools/export_with_jianying.py`（子进程，负责把草稿 JSON 写成剪映草稿目录）。
- `launcher/ShipinCutLauncher.py`（可选 — 当前是 `.bat` 启动，目前不依赖 Python；后续要把入口也 Python 化时再考虑）。

这些脚本本身只用 stdlib（`os sys json re shutil tempfile subprocess http.server pathlib datetime argparse winreg` 等），真正的“重”依赖在它们 import 的站点包上。

Python 站点包 / 原生依赖：

- `pyJianYingDraft`：剪映草稿核心，已随安装包 vendored 到 `tools/pyjianying_runtime/pyJianYingDraft/`。
- `pymediainfo`：读取视频元信息，vendored 到 `tools/pyjianying_runtime/pymediainfo/`，**包含原生 `MediaInfo.dll`**（Windows 64 位）。
- `comtypes`：pyJianYingDraft 间接依赖（Windows COM），vendored 到 `tools/pyjianying_runtime/comtypes/`。
- `uiautomation`：可选，pyJianYingDraft 间接依赖，vendored 到 `tools/pyjianying_runtime/uiautomation/`。

外部二进制（不是 Python 包，但是是运行依赖）：

- `ffmpeg` / `ffprobe`：从 `D:\ffmpeg\bin` 拷出到 `local-tools/ffmpeg/`，再被 `_find_local_tool` 命中；本机构建机才有。
- `tools/whisper/`：whisper.cpp 二进制 + `ggml*.dll` + 模型 `models/*.bin`，由后端直接 `subprocess` 调 `whisper-cli.exe`；本地存在时打入安装包。
- 剪映草稿目录：写到 `%LOCALAPPDATA%\ShipinCut\workspace\drafts\…`。
- 视频/音频/图片上传目录：写到 `%LOCALAPPDATA%\ShipinCut\workspace\{videos,audio,images}\…`。

Python 解释器本身：

- 当前由系统 PATH 上的 `python.exe` 承担。
- 版本要求见仓库根 `tmp/pyjianying_probe` 探针 venv（构建机自检脚本），运行后端即可。

## 3. 三种路线对比

### 方案 A：PyInstaller 打包后端 exe

**做法**

- 把 `tools/local_export_server.py`（及必要的子脚本）用 PyInstaller 打成 `local_export_server.exe`。
- 同时把 vendored 站点包（pyJianYingDraft / pymediainfo / comtypes / uiautomation）一起打进 exe。
- 把 `MediaInfo.dll` 显式加入 `--add-binary`，并让 `pymediainfo` 能在解包目录里找到它。
- 启动器改调 `{app}\backend\local_export_server.exe`，不再依赖系统 Python。

**优点**

- 普通用户体验最好：双击桌面图标 → 后端自启，**不要求用户装 Python**。
- 启动入口收敛到一个 exe，调试时能直接打日志。
- 路径处理简单（PyInstaller 解包到 `%TEMP%/_MEIxxxxx`，逻辑文件全部在 exe 内部）。

**风险 / 代价**

- 打包体积偏大（PyInstaller 打包 Python 解释器 + stdlib + 站点包，估计 30–80 MB）。
- 杀毒软件对 PyInstaller 产物误报概率高，可能需要代码签名或白名单说明。
- `winreg` 这种 Windows-only stdlib 模块在打包时需要 `--hidden-import` 显式列出，否则会被树摇掉。
- `MediaInfo.dll`、`tools/pyjianying_runtime/*` 这些 vendored 内容需要 `--add-data` / `--add-binary` 全部塞进去，spec 写起来需要小心。
- PyInstaller 一次解包到 `%TEMP%` 启动慢几百 ms（首次冷启动可接受）。
- 子进程 `subprocess` 调起的 `export_video.py` / `export_with_jianying.py` **要么也打成 exe，要么仍然依赖系统 Python**；3C 建议把这两个一并打包，否则 3C 反而退化成“半 Python 化”。
- PyInstaller 升级时 API 变化大，需要锁版本、CI 验证。

### 方案 B：内置 embeddable Python runtime

**做法**

- 随安装包带一个 Python **embeddable** 发行版，例如 `python-3.11.x-embed-amd64.zip` 解压到 `{app}\runtime\python\`。
- 启动器调 `{app}\runtime\python\python.exe tools\local_export_server.py`，解释器路径硬绑定。
- 在构建机上用本地 pip 把 `pyJianYingDraft / pymediainfo / comtypes / uiautomation` 装到 `{app}\runtime\python\Lib\site-packages\`，随包带走。
- 启动器设置 `PYTHONPATH` 指向 `tools\pyjianying_runtime\` 和 `runtime\python\Lib\site-packages`。

**优点**

- 比 PyInstaller 更透明：装包后目录里能直接看到 `python.exe` 和 site-packages，调试 / 升级可控。
- 不引入额外的二进制加壳 / 解包层，杀毒误报概率低。
- 子脚本（`export_video.py` 等）不需要单独打包，继续以 `.py` 形式存在，**直接复用 3B 的 subprocess 链路**，改造成本最小。
- 后续升级 Python 版本只需替换 embeddable zip，路径处理明确。

**风险 / 代价**

- embeddable 发行版本身不带 pip，需要手动 `get-pip.py` 装 pip；或者干脆在外部 venv 装好站点包后整体复制 `Lib\site-packages\`。
- embeddable 默认禁用 site-packages，需要 `python311._pth` 里加 `import site`，否则 `import pymediainfo` 会失败。
- 目录体积依然偏大（embeddable 解释器 + site-packages 约 30–50 MB）。
- 第一次升级依赖要重做“外部 venv 装包 → 拷贝 site-packages”的流程，文档化要做扎实。
- Windows embeddable 不带 Microsoft Store Python 那个 `py.exe` launcher，路径要写死或自己包一层。

### 方案 C：继续依赖系统 Python，做环境检测

**做法**

- 3B 后保持现状，启动器检测不到 `python.exe` 时给清晰提示 + 跳转到下载页。
- 不改运行入口逻辑。

**优点**

- 改动最小，本轮就能交付。

**缺点**

- 仍然要求用户手动装 Python。
- 不适合发给“普通学员” / 非开发者。
- 与 3C 目标“用户不需要安装 Python”不收敛。

## 4. 推荐路线

**先做方案 B 的最小 POC，方案 A 留作 3C-2 备选。**

理由：

1. **3B 刚通过，启动器主流程稳定**。方案 B 不动 `subprocess` 调起子脚本的链路，只是把“解释器从系统 PATH 改到 `{app}\runtime\python\python.exe`”，**改动面最小，回滚最容易**。
2. **pyJianYingDraft / pymediainfo 是 Python 站点包**，方案 A 把它们冻进 exe 后，调试和升级都得重建 exe；方案 B 仍然以 `.py` 形式落地，下次升级依赖只动 `runtime\python\Lib\site-packages\`，更轻。
3. **方案 A 的杀毒误报是真实痛点**。学员机器上 Windows Defender 一刀切拦截 PyInstaller 产物很常见，对内测可以，对普通学员不友好。方案 B 不加壳，目录里就是普通 `python.exe`，误报显著低。
4. **方案 A 的“子脚本也打包”要求扩散改动**。3B 里 `local_export_server.py` 是用 `subprocess` 调 `export_video.py` / `export_with_jianying.py` 的；方案 A 要么把这两个也打成 exe（增加 spec 维护量、调试变难），要么保持子脚本仍是 `.py`（那主进程打包就意义不大）。方案 B 一次解决。
5. **方案 C 是兜底，不能当主线**。3C 目标就是摆脱系统 Python，方案 C 等于不做。

如果 POC 暴露 embeddable Python 的隐藏坑（典型：site-packages 没启、tkinter / venv 模块缺失），再切到方案 A。两条路都建议先在干净 Windows 机器上做 POC，不要直接换主启动器。

## 6. POC 验收标准（3C-2 出口）

POC 通过需要满足：

- 模拟“没有系统 Python”的环境：把 `PATH` 上的 `python.exe` 改名 / 移到不会被自动找到的位置后，后端仍能启动。
- 启动器 / bat 调 `{app}\runtime\python\python.exe tools\local_export_server.py`（或等效命令）成功监听 8765。
- `GET /health` 返回 200。
- 浏览器能打开 `http://127.0.0.1:8765/shipin-cut/`，页面正常显示。
- 字幕识别：选择一个短视频 → 后端调 whisper-cli → 返回字幕分段。
- 导出剪映草稿：能成功写到 `%LOCALAPPDATA%\ShipinCut\workspace\drafts\…`，剪映能导入。
- 打开草稿文件夹 / 尝试打开剪映 正常。
- 安装目录 `{app}` 不产生运行时写入（首次安装由 Inno Setup 写入，运行期只有 `%LOCALAPPDATA%\ShipinCut` 变化）。
- 不引入新的杀毒误报（至少在主流 Windows Defender 默认策略下能直接放行）。

## 7. 风险清单

- **打包体积**：embeddable Python + site-packages 估计 30–50 MB，PyInstaller 估计 30–80 MB。`installer/dist` 输出要从 ~几 MB 涨到几十 MB，要在 README 里说清楚。
- **杀毒误报**：方案 A 概率高，方案 B 低。POC 阶段至少在干净虚拟机上跑一遍 Windows Defender。
- **Windows 路径空格 / 中文**：`{app}` 在用户机器上可能是 `C:\Program Files\ShipinCut` 或含中文目录，所有 `subprocess` 调用要继续用 list 形式（不拼字符串），启动器对路径要做 quote。
- **`MediaInfo.dll` 找不到**：embeddable Python 下 `pymediainfo` 默认在 `os.path.dirname(pymediainfo.__file__)` 找 `MediaInfo.dll`，3B 已经把 `pymediainfo/` 整目录随包带走，3C 也要保留这条 vendored 路径。
- **pyJianYingDraft import 路径**：`local_export_server.py` 通过 `PYTHONPATH=tools/pyjianying_runtime` 挂上，3C 要在 embeddable Python 启动时显式 `sys.path.insert`，不要依赖 site-packages 自动发现。
- **whisper / ffmpeg 路径**：3B 已经有 `_find_local_tool` 兜底（`{app}\local-tools\ffmpeg\ffmpeg.exe`、`{app}\tools\whisper\whisper-cli.exe`），3C 沿用即可，**不要**改 `_find_local_tool` 的命中顺序。
- **剪映草稿目录权限**：写 `%LOCALAPPDATA%` 不需要管理员，3C 不要把剪映草稿写回 `{app}`，避免和 Inno Setup 卸载逻辑冲突。
- **用户目录数据迁移**：3B 已经把数据写 `%LOCALAPPDATA%\ShipinCut\…`，3C 不需要做迁移。**不要**在 3C 改 `resolve_writable_paths` 的逻辑。
- **升级路径**：embeddable Python 升级时，依赖包要重新安装到新 site-packages；建议在 `installer/README.md` 写明 “升级 Python → 重新跑 `tools/runtime_bootstrap/bootstrap_venv.py` → 重打安装包” 的流程。
- **开发态 vs 安装态**：`启动视频混剪工具.bat` 在仓库根运行仍然要继续 work（开发态用系统 Python 跑）；3C 不要把开发态也强制走 `{app}\runtime\python`，会破坏开发流程。
