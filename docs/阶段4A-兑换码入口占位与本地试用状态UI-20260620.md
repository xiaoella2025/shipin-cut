> **本轮定位**：在 v0.5.0 稳定底座上做"兑换码入口占位 + 本地试用状态 UI"。**仅本地模拟**，不接真实后台、不做远程授权、不做付费系统、不锁功能。

## 1. 本轮目标

1. 在页面顶部右侧增加"激活状态"徽章：试用中 / 已激活 / 状态未知 / 未激活
2. 点击徽章打开"激活工具"弹窗：输入兑换码 → 调用后端 → 成功 / 失败温和提示
3. 状态持久化到 `%LOCALAPPDATA%\ShipinCut\config\activation.json`
4. 页面刷新后仍能读取本地 `activation.json`
5. 错误兑换码**绝不**阻断工具使用
6. 不影响字幕识别、剪映草稿导出、桌面启动器、embedded Python / 8765 / dist 静态前端链路

## 2. 当前不做真实后台的原因

- v0.5.0 收口刚定，3C 整条链路（启动器 / embedded Python / 8765 / dist）需要先稳定一段时间，再加远程调用

- 本轮**只**在本地模拟，把"激活"这条产品概念在 UI + 本地配置层先打通
- 4B（真实授权后台）会沿用本轮的 UI 与本地状态文件结构，**前端**几乎不需要再改

## 5. activation.json 结构

激活成功时：

```json
{
  "status": "activated",
  "code": "SHIPIN-TEST-2026",
  "activatedAt": "2026-06-21T16:00:34",
  "source": "local-placeholder",
  "version": "4A"
}
```

字段说明：

- `status`：当前固定为 `"activated"`（4A 成功状态；trial / unknown 不落盘）
- `code`：用户输入的测试码
- `activatedAt`：ISO 8601 时间戳
- `source`：`"local-placeholder"`（4A 占位标志，4B 接后台后会改为 `"remote"` 或类似）
- `version`：`"4A"`（标记 schema 版本，方便 4B 升级）

## 7. 后端 API

### 7.1 `GET /activation-status`

- 无请求体
- 200 返回：

```json
{
  "ok": true,
  "status": "trial" | "activated",
  "activation": { ... } | null,
  "version": "4A",
  "message": "..."
}
```

- 文件不存在 → `status: "trial"`, `activation: null`, `source: "default-local-trial"`, **不**写盘（懒写盘）
- 文件存在且 `status: "activated"` → 返回文件内容 + `message: "当前设备已激活..."`
- 失败时**绝不**返回 `inactive` 或 `locked`，4A 不在状态机里

### 7.2 `POST /activate-code`

- 请求体：`{"code": "..."}`
- 200 成功返回：

```json
{
  "ok": true,
  "status": "activated",
  "activation": { ... },
  "version": "4A",
  "message": "激活成功"
}
```

- 200 失败返回（**不**是 4xx，UI 处理更简单）：

```json
{
  "ok": false,
  "status": "trial",
  "message": "兑换码无效，当前仍可继续试用。"
}
```

- 失败场景：缺 code / 空 code / 错误 code / 安全断言失败 / 写盘异常——**全部**返回 200 + `ok:false + status:trial`，**绝不**改写当前激活状态

### 7.3 端口可覆盖

- 默认端口仍是 8765
- 测试可用 `SHIPIN_CUT_PORT=18765 python tools/local_export_server.py` 启动到任意空闲端口
- 该环境变量只用于本地开发 / 自动化测试；安装版 / 启动器不会设置
